# v1.0 Windows review — 2026-11-05

Branch `release/v1.0-windows`, based on `codex/desktop-voice-slim` (`1149134`). Goal: a Windows user installs from the website and Anna runs. Scope: digital-life core, voice, appearance; no gateway or vision.

## Reported on v0.6

1. Installing took very long to unpack.
2. The installed app opened with errors that looked like `.mjs` errors. The exact text has not been captured, so the cause on v0.6 is unconfirmed.
3. The competition requires running locally on an Intel Windows PC.

## Evidence

Measured from the Windows package of candidate `5cb0522`, built by the same packaging as v0.6: 132,172 files, 1,508 MiB unpacked, 129,064 files under `.pnpm`, 8,484 `.mjs` files, 512 MiB of type declarations and source maps. Linked pnpm packages were dereferenced into repeated copies. With a typical install prefix the longest path reached 266 characters. The v0.6 release workflow installed and removed the app but never started it.

The later asar candidate failed Windows startup in CI with an empty error stream: run 42013633567. Its cause is unknown. The reviewed hypothesis that asar mishandles absolute junction targets was false for asar 4.3.1.

## Changes

- Runtime dependencies are staged as a plain tree with no links, then archived. Staging refuses links, and Windows packaging refuses paths over 190 characters.
- Native files are actually unpacked; the previous glob matched nothing.
- A new `boot` entry reports a main-process load failure in a log and a dialog.
- Core output, exit codes, window failures and graphics status go to `<data>/logs/anna.log`, with recognizable credentials masked. A failure before the first snapshot now shows on the boot screen.
- Corrupt `settings.json`, `memory.json`, `journal.json` and `memory-dismissed.json` are kept in `<data>/quarantine`. If they cannot be set aside, startup stops instead of risking the only copy. An undecryptable key asks again and leaves its file alone.
- The installer removes old installs with long-path support and stops if it cannot, because Electron prefers a leftover `resources/app` over the archive. The installer script is read as UTF-8.
- `pnpm smoke:package [executable]` starts a package or install against an empty data folder. Release runs it on the macOS and Windows packages, on the installed Windows app and on the installed deb, whose path differs from the tar.gz.
- Windows enables software WebGL as a fallback; the Live2D stage reports missing WebGL and reloads after a restored context.

## Review findings

Standards, spec and re-review ran as independent sub-agents.

- Blocker, fixed: `boot` did not await main, so data folder and graphics switches could apply too late.
- Blocker, fixed: a core failure before the first snapshot was invisible.
- Major, fixed: credential redaction gaps; quadratic redaction; wrong-shape JSON still crashed; failed quarantine could lose the only copy; smoke could pass after a core exit or hang; unpack glob; installer charset.
- Minor, fixed: notice ordering and overwrite, quiet-mode dialog, byte-order marks, stage recovery.
- Blocker, open: voice is unreachable on a clean machine. Local mode needs a separately prepared service; cloud mode has no presets. This needs a product decision.
- Major, open: installer and update downloads come from GitHub only; pi downloads `rg` and `fd` from GitHub on first use; onboarding requires a verified model, and pi requires a key even for a keyless local model.
- Minor, open: 19.7 MiB of duplicate content from peer variants; Electron locales are untrimmed; the installer is unsigned; `Anna.exe` keeps Electron's icon and metadata.

## Building all three on one Mac

The runtime has no platform-selected packages, so only Electron differs per target. `scripts/electron-dist.mjs` downloads the target's Electron and holds it to the checksum pinned by the npm package. The review found and fixed: a checker that would always fail on Windows, a missing `libgbm1` in the deb's dependencies, Mac extended attributes and the builder's user name in the Linux archive, `.DS_Store` in the app, and release artifacts whose folder layout would have broken publishing.

`pnpm verify:package windows|linux` checks executable architecture, native addons, dependencies, links, leftovers, version and path lengths. It does not prove that a package runs.

## Local agent tools and cloud voice — 2026-11-06

Direction from the owner: every model capability (LLM, recognition, synthesis) goes through cloud APIs, and the agent ships inside Anna and runs locally, with nothing else to install.

### Changes

- **ripgrep and fd ship in every package.** pi's grep and find tools look for `rg` and `fd` in `~/.pi/agent/bin` and then on `PATH`, and otherwise download them from GitHub on first use (`tools-manager.js` `ensureTool`). That fails offline or where GitHub is blocked. `scripts/search-tools.mjs` pins ripgrep 15.2.0 and fd 10.5.1 for win32-x64, linux-x64 and darwin-arm64 by the SHA-256 GitHub publishes for each asset, caches them in `.data/search-tools`, re-checks the cache on every use, and copies only the executables into `resources/bin`. The packaged main process puts that folder first on the core's `PATH` (`packages/shared/search-path.ts`; on Windows it rewrites the existing `Path` key instead of adding a second spelling). The same `rg` satisfies the sandbox runtime's `which rg` on Linux, so the deb no longer recommends ripgrep.
- **`verify:package`** now fails a Windows or Linux package whose `resources/bin` tools are missing, built for another architecture, or (Linux) not executable.
- **Voice starts in the cloud.** New recognition and synthesis forms start on **云端 API** with a SiliconFlow preset (`https://api.siliconflow.cn/v1`, `FunAudioLLM/SenseVoiceSmall`, `FunAudioLLM/CosyVoice2-0.5B`, voice `FunAudioLLM/CosyVoice2-0.5B:anna`); only the key is missing. The local preset (`127.0.0.1:17861`) is still one switch away. Saved settings are unchanged.
- **The packaged core runs pi offline** (`PI_OFFLINE=1`, `packagedCoreEnv`): a missing tool is reported instead of fetched, and pi makes no version or catalogue checks. The bundled folder and `PI_OFFLINE` also reach the agent's own shell commands.
- **One key per service.** When recognition and synthesis have the same saved address, a key saved for one also serves the other (`keyFor` in `packages/voice/service.ts`). A key is still only sent to the address it was saved with.

### Review

Two independent reviews (Standards and Spec) found no blockers. Fixed:

- Should-fix: tar.gz extraction called bare `tar`, which on Windows can be Git Bash's GNU tar and fails on `C:\` paths; now `systemTar()` (System32 bsdtar) as `electron-dist.mjs` already did.
- Should-fix: tool and Electron downloads had no timeout; now 5 and 15 minutes.
- Should-fix: nothing checked the Mac bundle's tools; `package-mac.mjs` now runs each after signing, and `smoke:package` runs the bundled `rg`/`fd --version` on every platform before starting the app, which also catches quarantine, antivirus or architecture refusals on the target machine.
- Should-fix: pi could still download if `resources/bin` broke; the packaged core now sets `PI_OFFLINE=1`.
- Should-fix: a synthesis reply labelled `application/octet-stream` or `audio/wave` was rejected; the header of the audio itself now decides.
- Nits fixed: `arch` is required for staging; the cache is unpacked from the verified bytes, not re-read; duplicate `PATH` spellings documented; a trailing-slash key-sharing test; docs wording.

A re-review of these fixes found no blockers; its follow-ups are fixed too: the smoke test resolves the deb's `/usr/bin/anna` link before looking for the tools, the Mac tool check has a timeout, and an AAC (ADTS) header is no longer taken for MP3.

Not changed, with reasons:

- No `darwin` target in `verify:package`: the Mac bundle has a different layout and is not the finals' platform; running its tools after signing and in the smoke test covers presence, architecture and signing.
- A cleared key still shares the other side's key at the same address. It is never sent elsewhere; documented in `docs/voice.md`.
- A saved form moved by hand onto the other form's address without ticking 替换密钥 is still rejected by the re-key rule. Using the mode switch sets that box; relaxing the rule would let an old key follow a new address.
- The recognition form still sends an ignored `voice` field; `validateSpeech` drops it.
- A user saves each form once. Saving one does not also save the other.
- pi checks `~/.pi/agent/bin` before `PATH`, so tools from a separate pi install win. They are the same tools.

### Verification (macOS arm64, this tree)

## Xiaomi MiMo speech as the default — 2026-11-06

The owner bought a Xiaomi MiMo Token Plan and asked for MiMo speech as the default.

### Findings before the change

With the owner's key (used only from a private scratch file, deleted afterwards, never in the repository), `GET /v1/models` on `https://token-plan-cn.xiaomimimo.com/v1` lists `mimo-v2.5-asr`, `mimo-v2.5-tts` (plus voice design and cloning) and `mimo-v2.6-flash`/`-pro`. `POST /v1/audio/speech` returns 404: MiMo does speech through `/chat/completions` (official docs, read in the browser). The SiliconFlow preset written earlier was therefore never usable with this account, and SiliconFlow itself was never reached from this machine. The command sandbox blocked these hosts; outside it, TLS handshakes to MiMo still failed intermittently on both the direct and the proxied route, so the venue network needs its own check.

### Changes

- `VoiceProtocol` (`audio` | `chat`) on each saved speech config; settings without it stay on `audio`.
- `chat` synthesis sends the text as the assistant turn with `audio: { format: 'wav', voice }` and reads `choices[0].message.audio.data`; the decoded bytes must be WAV, MP3, Ogg or FLAC by their own header. `chat` recognition sends the WAV as an `input_audio` data URL, refuses more than 10 MB of base64 before uploading, and reads `choices[0].message.content`.
- The cloud preset is MiMo's Token Plan (`mimo-v2.5-tts` voice 冰糖, `mimo-v2.5-asr`); the form has a **接口格式** selector and tells pay-as-you-go `sk-` users to use `https://api.xiaomimimo.com/v1`.

### Review

Two independent reviews (Standards and Spec) found no blockers. Two re-reviews of the fixes found no blockers either. Fixed:

- Too-large chat synthesis replies said 识别结果过大; `boundedBody` now takes its message.
- The "broken body" test never reached the JSON parse failure; it now sends raw text. Truncated reply base64 is refused.
- HTTP errors now say what to change: 401/403 a key that is invalid or does not match the address (with MiMo's `tp-`/`sk-` rule only for MiMo hosts), 404/405 the address or 接口格式.
- The chat recognition limit counts the data URL prefix against 10,000,000 characters; tested on both sides.
- A new user saved twice. Saving one side on the cloud preset now also saves the other side if it was never set up and is untouched (`apps/desktop/src/voice-save.ts`, tested); only a successful second save refreshes the other form, and each partial failure says which side was saved.
- In conversation each sentence waited for its own synthesis, seconds of silence with a cloud service. `SpeechSession` now synthesises the next sentence while the current one plays, and cancels it on stop or on a playback failure.
- The desktop scripted flow now recognises through the chat protocol against a loopback fake; synthesis stays on the audio protocol, so both run end to end.
- Nits: MiMo's built-in voices are suggested in the form; the pay-as-you-go address comes from one constant; chat recognition replies may be 256 KiB (escaped Chinese); docs restructured.

Not changed, with reasons:

- No style instruction (user turn) is sent; a fixed tone would apply to all five companions. No `asr_options.language`; MiMo detects Chinese and English itself, and the real run was exact.
- One voice for all companions; per-companion voices are a separate feature.
- With prefetch, a request is usually pending while she speaks, so saving settings mid-reply is refused more often ("请先停止正在处理的语音").
- If `voice-status` fails when the sheet opens, a stored side reads as unsaved and could be overwritten by the preset on the same address; configure would normally fail too.

### Verification

- Tests first: the chat-protocol, preset, save and prefetch cases failed before each implementation. Lint and typecheck pass; 781 tests passed, 19 skipped.
- Real key, through Anna's own `VoiceService` bundled with esbuild (a retry wrapper around `fetch` only for this Mac's flaky handshakes), before and again after the review fixes: synthesis returned a WAV (176,684 and 161,324 bytes); recognition returned the sentence ("你好，我是安娜。今天想一起做点什么？", the second time with a comma for the first full stop) in 4.6 and 2.0 s; the key was saved once and served both directions; status never contained it. Synthesis took 4.6 s the first time and 38.6 s the second, so latency on this network varies widely.
- All five packages rebuilt: Windows installer 138,151,454 bytes (SHA-256 `094bddb6525583544…`), Windows zip 191,380,760, deb 115,308,220, Linux tar.gz 156,289,862, Mac zip 161,369,308; `app.asar` SHA-256 `13098c4e6875edf8…` on all three. `verify:package windows|linux`, `smoke:package` and `test:scripted` on source and on the packaged Mac app pass.
- Not verified: the key typed into the app's own form (left to the owner), playback and lip sync with MiMo's 24 kHz audio on real hardware, prefetch timing with a real service, Windows, and the venue network.

## Fixes for the Windows acceptance findings — 2026-11-06

Branch `fix/v1.0-gpu-log-and-shell`, into `release/v1.0`.

- **Graphics line.** It is now written once, after the first page load, from `app.getGPUInfo('basic')` and the feature status at that time (`packages/shared/graphics.ts`). It names the active GPU, for example `graphics: webgl enabled, gpu 106b:0000 (Apple)` on the build Mac. Electron 44 returned no `webgl2` entry, so the field is left out instead of written as `undefined`.
- **No `shell: true` launches with arguments in the core on Windows.** `scriptLaunch` (`packages/agents/windows-shim.ts`) starts a Windows script from an argument list:
  - Programs start as they are.
  - npm shims become node plus their script, and Node's own `npm.cmd` becomes node plus `npm-cli.js`.
  - A `.ps1` goes to the system `powershell.exe -File`.
  - Any other `.cmd` goes to `cmd.exe /d /v:off /s /c` verbatim, but only when the path and every argument are plain (no spaces, quotes, `% ! ^ & | < > ( ) , ;`, line breaks or non-ASCII). Otherwise it refuses with a message.
- **Where `scriptLaunch` is now used.**
  - Agent detection (`node-environment.ts`).
  - Agent install (`agents-hub.ts`, through `install-launch.ts`).
  - Delegation (`runner.ts`): the task text is an argument, so it can never reach cmd.exe. A refused agent fails before any provider file is written.
  - The Codex metadata connection (`codex-rpc.ts`).
- **Installs find npm through the same search directories as agents.** The command's or npm's folder goes first on the child's `PATH`, through `withSearchTools`, which handles Windows' `Path` spelling. This lets `#!/usr/bin/env node` work for nvm and fnm users.
- **Remaining `shell: true`.** The only one is the ACP kernel. It runs one sandbox-wrapped command line with each argument single-quoted, and ACP is never offered on Windows.

Review: Standards and Spec reviews ran in parallel. The Spec review's blocker (delegation in `runner.ts` still used a shell) and the should-fix items were fixed: PATH for npm, `/v:off`, `.ps1` support for Codex, tests for an opaque `npm.cmd` and for the refusal. A re-review found no blockers; its nits were fixed too: the full PowerShell path, and refusing before writing provider files.

Accepted risk: an agent found only as a `.ps1` runs through Windows PowerShell 5.1, which may mangle a `"` or an empty argument passed on to node. Detection prefers `.cmd` and `.exe`, so this path is rare. It has not been run on Windows.
