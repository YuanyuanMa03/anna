# Anna 服务工作台与独立网关

日期：2026-11-04。状态：数据入口、共享工作台与桌面入口已实现，可试用；使用与限制见 `docs/gateway-workbench.md` 和 `docs/gateway-deployment.md`。现有后端/模型未迁移；本机新增回环数据入口 17864 与工作台 17865，未修改旧设备地址或 Key。

## 产品决定

放在 Anna 原仓库维护，一套服务契约和工作台界面，两种运行方式：Anna 桌面内置入口，以及不依赖 Electron 的独立网关与网页工作台。用户通过 Git 获取同一版本；服务器不必安装 Anna 桌面。

语言模型、语音识别、语音合成都属于网关能力。当前 Mac mini 不启动本地语言模型，可以转发用户配置的云端语言模型或其他机器上的模型服务。产品支持语言模型，与当前机器是否运行语言模型分别管理；当前冻结根因未确认，不把这次架构调整描述为根因修复。

首版保留自用定位：设备 API Key、实际用量、内部额度与手动加额；不加入真实支付或售卖订阅。内部额度不是服务商账户余额。

## Anna 里的使用路径

首页保持角色、对话和任务为主，增加小型“服务工作台”入口，也可从 Anna 档案进入。工作台使用完整页面和返回 Anna 按钮，不把五个管理页面塞进设置弹窗。

首次进入分成两个明确动作：

1. “让这个 Anna 使用服务”：连接已有网关，填写地址和设备密钥，在模型与感官设置中选择相应路线。
2. “向其他设备提供服务”：在本机创建网关，或连接已部署网关的管理端；配置服务来源，再给设备发放密钥。

普通用户不必成为网关管理员。选择远端网关不会隐式启动第二个本地实例。独立部署的网关不随桌面退出；桌面创建的临时实例默认随桌面退出，保持后台运行必须明确选择。两种生命周期显示在部署页。

## 工作台与 Anna 元素

沿用已选“温柔工作台”：暖纸色、墨色文字、苔绿色强调，主要容器 22px 圆角，支持深色模式。五项导航：总览、服务接入、设备密钥、用量额度、部署连接。

- 总览显示 Anna 的名称与头像、小型角色区，以及“文字思考 / 听见声音 / 说出回应”三项真实服务状态；旁边保留 LLM、ASR、TTS 标识。离线、待验证、可用、失败、未知分别呈现，不把服务健康等同于真实推理成功。
- 名称和形象沿用原仓库的角色来源；独立部署使用随版本提供的默认形象，展示个人外观需主动发布。首版使用静态缩略图，不要求管理浏览器持续运行完整 Live2D。角色素材须分别核对可分发许可。
- Anna 的引导来自确定的状态与帮助文案，例如“还差一个声音来源”；不为查看页面调用模型，不编造她正在做的工作。
- 服务卡显示来源、实际模型、云端/本机/其他节点、能力、状态与最近验证时间。模型详情内提供文字、音频上传及生成测试；用户主动运行才产生推理调用，音频默认不自动播放。
- 发放密钥后展示 Base URL、模型别名、复制配置和调用示例。密钥只展示一次，之后可撤销重建；不放入二维码 URL、浏览器持久存储或日志。
- 请求记录展示 request ID、实际模型、耗时、用量和失败原因；未知值显示未知。没有数据时展示空态，不用演示数字填充生产界面。

厂商式体验来自完整闭环：接入服务 → 验证 → 发放设备密钥 → 复制调用配置 → 查看实际请求与额度 → 诊断错误。充值只称“手动增加内部额度”，不模拟付款成功。

## 连接方式

| 模式 | 使用场景 | 首版边界 |
| --- | --- | --- |
| 本机 | 同一台电脑上的 Anna 或其他程序 | 默认监听 127.0.0.1 |
| 局域网 | 同一 Wi-Fi / 有线网络中的手机、电脑 | 主动选择网卡/监听地址；提示防火墙与访客网络隔离；每设备密钥；纯 HTTP 会明确提示链路不加密，推荐 HTTPS 或受控网络 |
| Tailscale | 已有 Tailnet 的设备 | 可选接入，不作为安装或使用前提；与公共 HTTPS 模式分开 |
| 公共 HTTPS | 没有 Tailscale、需要跨网络的设备 | 接入现有域名、反向代理或隧道；明确目标监听、证书、鉴权与限流；不自动开放路由器端口 |

独立页面提供“我已有 HTTPS 地址”的配置与部署说明；首版不同时内置所有隧道厂商的账号和域名管理。没有域名的用户可按文档选择外部隧道，接入能力由具体方案验证，不能承诺各地区网络都可用。

数据 API 与管理端分别绑定/发布。开启外部 API 不自动开放管理端；管理端默认本机或私网，可选远程管理须独立认证、会话保护与 TLS。设备 Key 不能登录管理端，管理页面不能凭访问页面直接取得管理员能力。Web 管理端使用受保护会话与明确来源策略，数据 API 默认不放开任意跨域。

“服务正在监听”“局域网地址可达”“其他设备已成功调用”是三种不同证据。连接页展示最后检查时间；本机访问自己的地址不算跨设备验收。

## 原仓库融合位置

已核对当前结构：`apps/desktop/core.ts` 承载 Host 与感官调用；`packages/routing/server.ts` 是本机 agent 路由，并拒绝带 Origin 的请求；`packages/character/manifest.ts` 提供角色配置。现有路由不是对外网关，不能把监听地址从 localhost 改为 0.0.0.0 就交付。

目录结构（前三项已创建；分平台安装脚本仍待交付）：

```text
apps/gateway/                   独立服务入口、构建与运行命令
packages/gateway/               契约、配置、后端适配、生命周期
packages/gateway-ui/            共用原生网页，Vue 桌面通过受限 iframe 嵌入
scripts/gateway/                分平台准备、启动、停止、诊断
```

沿用现有源码共享方式：当前 pnpm workspace 只枚举 `apps/*`、`plugins/*`，上述 `packages/*` 先作为共享源码目录；若改为独立依赖包，需显式调整 workspace 和构建，不假定已经是可发布包。

桌面通过受控 IPC 获取本机工作台链接，再通过同一网页与管理 API 使用同一实例；独立入口无需前端构建。前端不读凭据库或数据库。网关有独立进程、数据目录和实例锁，同一数据目录不允许多实例并发写入。工作台登录有独立管理会话，正常浏览器支持 HttpOnly 会话恢复；设备与上游 API Key 不放入浏览器存储。

网关启动不构建或初始化 Host、Kernel、工作目录权限、会话记忆，也不导入 MLX/PyTorch 或下载权重。模型节点独立安装与运行，网关只连接已经启动的端点。当前独立目录中包含 MLX 的统一依赖与会自动启动 llm 的安装脚本不能直接迁入默认入口。

原有模型路由继续服务本机 agent；首版通过明确配置让 Anna 作为网关客户端，复用其密钥隔离和格式转换，不重写全局路由。后续只提取确有重复且经过测试的纯协议代码。

## 服务发布、身份与数据

Anna 已有提供商不自动成为可共享服务。用户主动选择“发布到网关”，确认模型、范围、额度和数据去向。桌面本地实例可受控取得特定凭据；独立部署需在服务器自己的凭据库重新配置，不把本机凭据文件复制到服务器。

agent 的网页登录、个人订阅和终端令牌不当作可转售/转发 API；仅接入有明确 API 调用授权的来源。向设备发放的是网关设备 Key，不是上游 API Key。

网关只提供模型推理，不向外发布 Anna 的记忆、聊天历史、文件、终端、Skills 执行权或桌面控制权。其他设备要表现出同一个 Anna，由其 Anna 客户端负责人格与经授权的上下文，不能因用了同一 API 就宣称人格/记忆已经同步。

首版接口目标：`GET /v1/models`、`POST /v1/chat/completions`（SSE）、`POST /v1/audio/transcriptions`、`POST /v1/audio/speech`。实际验证通过的能力才公布；Responses、原生 Anthropic、工具调用逐项解锁。提供 `anna-chat`、`anna-asr`、`anna-tts` 稳定别名，日志记录实际服务模型和路由版本。

LLM 归集实际输入/输出/缓存 token；ASR 记录音频秒数；TTS 记录输入字符与输出秒数。各单位分别呈现，统一扣减内部额度时公布换算规则版本。请求有唯一记录，预留、结算、失败退回具有原子性与去重；不能将服务端报告缺失的用量伪造成零。

默认不保存正文、录音或合成音频；错误信息脱敏。切换到云端或备用来源须事先明确授权数据范围；失败不会自动启动本地模型，流开始后不自动重试。模型节点的取消能力如实呈现，停止转发不等于底层计算已经结束。

## 实施批次与验收

### 三平台部署与本地优先

目标为 Windows x64、Linux x64、macOS arm64；macOS Intel x64、Linux arm64 单独标明证据，不能由其他架构推断支持。网关与各个模型节点分开验收，某平台能运行网关不等于能运行 MLX 或任意本地模型。

| 验收项 | Windows | macOS | Linux |
| --- | --- | --- | --- |
| 干净 Git 部署 | PowerShell、原生可执行程序与 `.cmd` shim | shell、arm64 依赖、系统权限 | shell、发行版/架构、系统依赖 |
| 数据与凭据 | 用户应用数据目录、DPAPI/明确受限存储 | Application Support、钥匙串授权 | XDG 数据目录、可用凭据库/明确受限存储 |
| 文件与进程 | 盘符/空格/中文/UNC、参数数组、子进程退出 | 空格/中文、签名与权限、子进程退出 | 空格/中文、可执行权限、信号与子进程退出 |
| 连接 | 选定网卡、Windows 防火墙、LAN 实机调用 | 选定网卡、系统防火墙、LAN 实机调用 | 选定网卡、主机防火墙、LAN 实机调用 |
| 生命周期 | 启动/停止/端口释放、重启默认不启动模型 | 同左；不依赖开发机 LaunchAgent | 同左；不要求 systemd 或 Docker 才可前台运行 |
| 升级与回退 | 备份/迁移/失败回退、旧设备 Key 有效 | 同左 | 同左 |

原生系统凭据库与受限文件方案分别报告，不能把“文件夹具通过”写成系统加密验收通过。启动脚本检查 Node/依赖版本，固定版本与校验值；网关安装不拉取推理库、ffmpeg 或模型，模型节点按所选能力另行准备。

先在本地审阅完整 diff，检查类型、相关测试、构建与必要桌面流程，修复明确问题后才推送。CI/真实听觉工作流仅手动触发，不用 PR 更新反复消耗三平台额度。稳定候选优先使用已有目标机器集中验收；缺平台时才用必要的手动 hosted 矩阵补证据。记录提交 SHA、OS/架构、命令与结果，不要求为文档改动跑三平台，也不以“本地没报错”保证没有缺陷。

### 开发顺序

1. **隔离与纳库**：拆开轻量网关、语音节点、可选语言模型依赖；默认不启动模型；建立独立生命周期和数据目录；审阅迁移与回滚。验证只启动网关时不加载模型，桌面退出与服务退出符合所选方式。
2. **Anna 工作台**：共享页面、角色元素、服务接入、设备 Key、实际请求、额度流水；先接已有语音端点，修复加额路径。验证无效/撤销/零额度 Key、并发扣费、失败退回、SSE/取消和脱敏；演示数据与生产状态隔离。
3. **多种连接**：本机、LAN、Tailnet、已有公共 HTTPS 入口。验证另一台真实设备调用，外部设备 Key 无管理权，未发布管理端不可访问，停止后无遗留监听。不要求客户设备安装 Tailscale 才能使用 LAN/HTTPS。
4. **原应用消费与比赛交付**：Anna 的文字/听觉/发声连接网关别名；经用户配置后验收一个云端 LLM。三平台从 Git 按锁定依赖部署，分别记录实测平台；比赛机重点复验 Intel 上的启动、资源、耗时及错误恢复。没有目标机证据前不宣称已完成跨平台验收。

比赛演示闭环：一台轻量服务节点 → 同一局域网另一台 Anna → 静音完成 ASR 与 TTS 文件验证 → 配置好的云端 LLM 完成短任务 → 工作台出现实际设备、来源和用量 → 撤销该设备 Key 后拒绝调用。突出“Anna 的能力可以跨设备提供，算力节点可替换”；不预先宣称 Intel 加速或 token 节省已经达成。

本文仅定义下一步开发目标，不代表这些能力已交付，不授权启动当前 Mac mini 的本地语言模型，也不执行公网开放。
